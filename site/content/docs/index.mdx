contentbit is the shortest path from "my agent wrote some Markdown" to
"this content is structured, validated, and ready to render." It adds a small
block protocol to Markdown, generates authoring instructions from your block
schemas, and gives your coding agent a repeatable write -> validate -> fix loop.

The contract is simple: authors and agents write Markdown with directive-style
blocks; every block has a schema; validation runs before anything renders:

First-time flow:

1. Run `init`.
2. Validate the starter document.
3. Ask your agent to write or audit content.

That gives you a working content system, not just a package install:

- **Content to edit:** `content/example.md` and `content/related.md`
- **A schema source of truth:** `blocks/registry.ts`
- **A visible render target:** `/example` when your framework supports it
- **Quality gates:** `content:check` and `content:links` scripts
- **Agent context:** `contentbit-guide.md`, `AGENTS.md`, and Claude Code skills
  when a `.claude/` directory exists

Skip the agent files with `--no-agents` if you only want the library and CLI.

## 2. Ask your agent

Your coding agent now has project-local instructions. Start with one of these:

> write a blog post about our new dark mode

> audit my content

The writing loop is deliberately boring:

1. Read the `content:check` script to discover the content glob and registry.
2. Fetch the live authoring guide from that registry.
3. Write plain Markdown with registered blocks.
4. Validate the file.
5. Fix diagnostics until validation exits 0.

The failed validation in this demo is the useful part: it gives the agent a
specific source line, stable error code, and fix hint.

This is reliable because the skills contain no schemas. They read everything
from the CLI at runtime (the authoring guide, the diagnostics, the stats), so
when you add a custom block, every agent picks it up on the next run with
nothing to regenerate. Works beyond Claude Code too: `AGENTS.md` carries the
same instructions for Cursor, Codex, Copilot, and friends.

## The validation contract

What makes the loop converge is the diagnostic format. Invalid content never
renders; it produces errors a machine can act on:

```text
content.md:12:3 error CB_ROW_COLUMNS
:::comparison rows require 3 columns (label | left | right). Found 2.
hint: Format: - label | left | right
```

Each diagnostic carries the exact source position, a stable code, and a fix
hint, so your agent (or your CI) can act on it. The same gate runs in the
editor loop, in `pnpm run content:check`, and before every render.

## Under the hood

Prefer wiring things up manually? Install the pieces directly:

```bash
pnpm add @contentbit/core @contentbit/blocks
pnpm add @contentbit/html   # static HTML strings
pnpm add @contentbit/react  # React components
pnpm add @contentbit/astro  # .astro components
```

The whole pipeline is three calls — parse to a source-mapped AST, validate
against the registry, render through the adapter of your choice:

```ts
import { createBlockRegistry, parseDocument, validateDocument } from '@contentbit/core'
import { genericBlocks } from '@contentbit/blocks'
import { renderToHtml } from '@contentbit/html'

const registry = createBlockRegistry().use(genericBlocks())

const result = validateDocument(parseDocument(markdown), registry)
if (!result.ok) {
  console.error(result.diagnostics) // code, severity, message, exact position
}

const html = renderToHtml(result.document)
```

In React, `ContentBlocks` ships headless, accessible defaults for every generic
block:

```tsx
import { ContentBlocks } from '@contentbit/react'

export function Article({ document }: { document: DocumentNode }) {
  return <ContentBlocks document={document} renderMarkdown={(md) => <Markdown source={md} />} />
}
```

One thing not to skip: Content Blocks parses **blocks only** — prose and block
bodies are handed to a `renderMarkdown` function you provide (react-markdown,
marked, markdown-it, remark…). Without it, `**bold**` renders as literal
characters. Step-by-step wiring for each library:
[Plug in your Markdown library](/docs/guides/markdown).

And if headless isn't your thing, a polished Tailwind-styled pack installs
through the shadcn registry — components land as editable source files you own:

```bash
pnpm dlx shadcn@latest add @contentbit/generic-pack
```
