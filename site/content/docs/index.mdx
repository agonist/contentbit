This tutorial takes a project from plain Markdown to a validated content loop:
install contentbit, inspect the starter document, run the quality gates, and ask
an LLM agent to write content that can be checked before it renders.

Contentbit adds typed directive blocks to Markdown. The blocks stay readable in
source, but each one has a schema:

<Live>
{`:::comparison{left="Basic" right="Pro"}
- Price | Free | $12/mo
- Support | Community | Priority
:::`}
</Live>

First-time flow:

1. Run `init`.
2. Validate the generated example.
3. Open the local content dashboard.
4. Ask your LLM agent to write or audit content.

The generated files matter:

- **Content to edit:** `content/example.md` and `content/related.md`
- **A schema source of truth:** `blocks/registry.ts`
- **A visible render target:** `/example` when your framework supports it
- **A local browser:** `studio` for read-only previews, health, links, and keywords
- **Quality gates:** `content:doctor`, `content:check`, and `content:links` scripts
- **Agent context:** `contentbit-guide.md`, `AGENTS.md`, and Claude Code skills
  when a `.claude/` directory exists

Skip the agent files with `--no-agents` if you only want the library and CLI.

## 2. Validate the starter content

Run the generated validation script before editing anything:

```bash
pnpm run content:check
```

The script expands to a `contentbit validate` command with the right content
glob and registry path for your project. Validation checks directive syntax,
block props, block body shape, and frontmatter-authored internal links when
your files declare slugs.

When validation fails, contentbit prints diagnostics with source positions and
fix hints:

```text
content/dark-mode.md:18:1 error CB_ROW_COLUMNS
:::comparison rows require 3 columns (label | left | right). Found 2.
hint: Format: - label | left | right
```

The exact same gate can run locally, in CI, and inside an LLM-agent repair loop.

## 3. Open Studio

Start the read-only dashboard:

```bash
pnpm run studio
```

Studio lets you browse rendered previews, source Markdown, validation findings,
document stats, links, backlinks, keywords, and block usage. It is a human view
over the same project scan that powers `contentbit doctor`.

## 4. Ask your LLM agent

Your LLM agent now has project-local instructions. Start with one of these:

> write a blog post about our new dark mode

> audit my content

The writing loop is deliberately boring:

1. Read the `content:check` script to discover the content glob and registry.
2. Fetch the live authoring guide from that registry.
3. Write plain Markdown with registered blocks.
4. Validate the file.
5. Fix diagnostics until validation exits 0.

The failed validation in this demo is the useful part: it gives the LLM a
specific source line, stable error code, and fix hint.

<AgentSession
  steps={[
    { kind: 'user', text: 'write a short post about our new dark mode' },
    { kind: 'skill', name: 'contentbit-author' },
    { kind: 'command', command: 'contentbit instructions --audience llm --registry ./blocks/registry.ts', exitCode: 0 },
    { kind: 'assistant', text: 'Drafting content/dark-mode.md with a callout and a before/after comparison.' },
    {
      kind: 'command',
      command: 'contentbit validate content/dark-mode.md --registry ./blocks/registry.ts',
      exitCode: 1,
      output: 'content/dark-mode.md:18:1 error CB_ROW_COLUMNS\n:::comparison rows require 3 columns (label | left | right). Found 2.\nhint: Format: - label | left | right',
    },
    { kind: 'assistant', text: 'The comparison row is missing its second value. Fixing and revalidating.' },
    {
      kind: 'command',
      command: 'contentbit validate content/dark-mode.md --registry ./blocks/registry.ts',
      exitCode: 0,
      output: '1 file(s): 0 errors, 0 warnings',
    },
  ]}
/>

The installed agent files contain no copied block schemas. They ask the CLI for
the current authoring guide, diagnostics, doctor reports, stats, and link graph
when they run. Add a custom block to `blocks/registry.ts`, and the next agent
session sees it without prompt surgery.

## 5. Install styled components

```bash
pnpm dlx shadcn@latest add @contentbit/generic-pack
```

The pack copies editable Tailwind React components into your app. Astro projects
can use:

```bash
pnpm dlx shadcn@latest add @contentbit/astro-pack
```

Headless rendering still works without these packs. Styled packs are only UI
source files you own after install.
